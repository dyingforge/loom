# 架构决策记录

本文件记录实现过程中已锁定的决策；与两份项目文档共同构成实施依据。

## D1 依赖只能向内（domain ← agent ← adapters）

按实施计划 1.2，依赖箭头仅 `adapters → agent → domain`。反向 import 一律禁止。强制方式：`server/tests/test_architecture.py` 通过 AST 扫描验证，CI 必跑。

## D2 不跨提供方降级

服务端不自动从 MiniMax 切换到其他模型。失败如实报告，由人工决策。

## D3 服务端不长期保存项目内容

服务端按次接收必要快照；运行日志只记录请求编号、耗时、用量和错误类型。模型提供方会收到规划所需内容（含任务标题），按 PRIVACY.md 说明。

## D4 密钥仅在服务端

客户端包内无密钥、令牌或登录表单；密钥通过环境变量在服务端注入。

## D5 无云端账户

单用户、单设备、应用内日历；首版不做云账户、同步、协作。

## D6 设备本地时间

所有时间块与排程按设备本地时间；首版不处理时区与夏令时。客户端读取设备时间，发送 ISO 字符串；服务端不转换时区。

## D7 撤销算一次修改，仅撤最近一次

撤销恢复日历安排，不覆盖变更之后录入的实际进度；旧安排因进度、依赖等当前约束已不合法时拒绝撤销。撤销生成新项目版本与变更记录，并作废旧版本待确认方案。

## D8 失败不返回预设答案

模型调用失败、超时、循环超限、达到上限时如实报告原因，不回退到固定算法，不隐藏结果。

## D9 限流与额度是 HTTP 中间件

按 IP 限流 + 每日费用上限 + 评审专用额度，全部在 `server/adapters/http.py` 同文件中实现；可单独关闭以测试。

## D10 校验器双实现、单向量

客户端与服务端 C1–C7 校验器独立实现，但共用 `vectors/` 测试向量。同一份输入两侧输出必须一致。

## D11 Python weekday 约定

`Project.restDays` 采用 Python `datetime.weekday()` 约定：`0=周一, ..., 6=周日`。周六周日写作 `[5, 6]`。这与 JSON 数据约定一致；客户端 Splash 也按此解释。

## D12 Splash 入口单文件

由于 `card-host` 子模块加载行为不完全可控，按 SCRIPT-API.md §"Shape of a program" 将客户端逻辑合并到单一 `main.splash`，避免依赖运行时未保证的能力。

## D13 测试替身仅在 tests/

`ScriptedLLM` 与真实模型共享同一 `ports.LLM` 接口，但实现仅放在 `server/tests/stubs.py`；运行时包绝不引入替身。运行时通过 `LOOM_USE_REAL_MODEL=1` 切换真实模型。
