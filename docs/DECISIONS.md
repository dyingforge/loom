# Loom 实现决策

## 单用户与应用内日历

初赛主流程管理单设备上的一个目标日历。用户提交目标与截止日期，模型拆分任务并生成每日安排，用户通过文字建议修改并确认计划。

## 真实模型与工具调用

MiniMax 接收完整项目、修改建议和对话，通过工具重构任务、检查依赖、查询可用时段并提交完整排程。服务保留提供方的助手消息和真实工具结果。模型错误立即终止请求并报告原因。

## 确认与保存核验

候选计划需要符合完整日历约束。客户端确认时检查版本与原始时间块，将完整候选内容保存后实际回读，由服务比较任务、安排和约束，形成核验回执。通过核验后更新正式计划。正式与候选计划分别保存，支持切换查看和重新启动恢复。

## 官方宿主与本地存储

原生宿主由 `native/LOCK.json` 固定的官方 OctoSense-App-Hub 提交及其 `Cargo.toml` 引用的 Makepad 与 Octoscript 构建，不使用私有原生改动。客户端保存、草稿、恢复和核验回读全部使用官方 `fs` 文件能力，不依赖自定义宿主服务。业务记录在应用目录交替写入 `state-a.json` 与 `state-b.json` 两份完整快照，写入后回读比较，失败即停止当前操作。

## 进度与时间

剩余工时表示当前时间之后需要安排的小时数。已经开始或完成的时间块保留原始事实。客户端固定东八区（UTC+8），项目使用该时区的无偏移日历时间；不读取设备时区文件，也不需要处理夏令时。

## 规划过程与使用记录

HTTP 接口先创建规划过程，再分次等待结果。服务最多同时处理四项规划，单次模型调用默认超时 60 秒。暂停状态、使用记录和预留额度保存在 SQLite 中；恢复沿用服务端计数。

费用采用提供方报告的 token 数量与配置价格估算。默认单位为美元分，输入按每百万 token 37.5 分的计价上限估算，输出按 120 分估算；该估算未扣除缓存优惠。未知用量保留调用前的额度预留。价格依据 [MiniMax 官方计价说明](https://platform.minimax.io/docs/guides/pricing-paygo)，部署者可通过环境调整。

## 客户端入口

`bundle/main.splash` 是客户端唯一入口，使用 Figma 的顶部品牌、目标输入、月历、当天安排与右侧计划说明。真实月份与日期使用 OctoScript 日历能力生成；任务安排使用服务返回的时间资料。本地记录在 `state-a.json` 与 `state-b.json` 间交替保存，写入后立即回读比较。
