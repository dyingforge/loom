# Loom 实现决策

## 单用户与应用内日历

初赛主流程管理单设备上的一个项目。日历由应用保存，用户维护剩余工时、完成事实、固定日程和工作安排。

## 真实模型与工具调用

MiniMax 接收完整项目和对话，通过工具检查项目、查询可用时段、提出任务和提交完整排程。服务保留提供方的助手消息和真实工具结果。模型错误立即终止请求并报告原因。

## 批准与独立复核

排程方案需要符合完整日历约束。服务端检查候选；客户端批准前独立复核版本、原始块与完整日历。实际保存后的文件回读由服务再次比较，形成核验回执。风险与例外需要批准当前方案。

## 进度与时间

剩余工时表示当前时间之后需要安排的小时数。已经开始或完成的时间块保留原始事实。用户填写 UTC 偏移，所有项目时间使用所在地的日历时间；跨夏令时项目需要用户维护偏移与时间安排。

## 规划过程与使用记录

HTTP 接口先创建规划过程，再分次等待结果。服务最多同时处理四项规划，单次模型调用默认超时 60 秒。暂停状态、使用记录和预留额度保存在 SQLite 中；恢复沿用服务端计数。

费用采用提供方报告的 token 数量与配置价格估算。默认单位为美元分，输入按每百万 token 37.5 分的计价上限估算，输出按 120 分估算；该估算未扣除缓存优惠。未知用量保留调用前的额度预留。价格依据 [MiniMax 官方计价说明](https://platform.minimax.io/docs/guides/pricing-paygo)，部署者可通过环境调整。

## 客户端入口

`bundle/main.splash` 是客户端唯一入口。日历检查使用 OctoScript 自带日历能力和服务提供的时间对应数据；本地记录采用交替快照和保存后完整回读比较。
